## 行為與影響

Windows 模式直接呼叫系統 Shell 的傳統完整選單，移除原先插入上方的 Winfinder 項目。單檔、多選、資料夾、目錄空白處、Shift 右鍵與 Shift+F10 均使用同一路由，extras 必須為空。既有重新命名與新增資料夾的 inline rename 流程保留。

檔案選單以 CMF_CANRENAME / CMF_ITEMMENU 宣告支援重新命名；Shift 仍要求擴充命令。[Microsoft QueryContextMenu 文件](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icontextmenu-querycontextmenu) 說明 CMF_CANRENAME 允許 namespace 提供 Rename。新增 Rust 測試實際建立系統 Shell 選單並確認 rename canonical verb 存在。

設定名稱改為「Windows（傳統完整選單）」。Windows 為既有預設；已明確選擇 Finder 風格的設定不強制覆寫。切換方式：設定 → 外觀 → 右鍵選單 → Windows（傳統完整選單）。

## 範圍與限制

使用者選定的是「顯示更多選項」的傳統完整選單。Windows 11 第一層精簡選單不在本次範圍。項目由 Windows 依檔案類型、系統版本及註冊的 Shell 擴充決定；測試沒有逐一安裝與驗證每一家第三方擴充。Winfinder 自有的常用頁虛擬項目及非 Windows 平台仍依原有可用選單處理。

本次不修改 PRD/SRS/SDD ID，不新增原生 API 契約，不重設使用者偏好。
